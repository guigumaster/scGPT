## 修复摘要

### Bug 1：`ImportError: cannot import name 'vocab' from 'torchtext.vocab'` ✅

**根因**：已安装的 `torchtext 0.6.0` 已移除 `torchtext.vocab` 中已弃用的 `vocab()` 工厂函数。`gene_tokenizer.py` 中的 `_init_from_tokens` 方法在 torchtext 后端路径中无条件地使用 `from torchtext.vocab import vocab`，导致崩溃。

**修复**：修改了 `scgpt/tokenizer/vocab_compat.py` 中的 `_probe_torchtext_vocab_subclassable()` 函数，以检查 `vocab` 工厂函数是否实际可导入。如果不可用（如 torchtext ≥0.6.0），即使 Vocab 类本身可被继承，也会回退到 `BuiltinVocab`。

**文件**：`scgpt/tokenizer/vocab_compat.py`（第 36-71 行）

---

### Bug 2：`ValueError: Number of features in data (1200) does not match number of gene_ids (2000)` ✅

**根因**：`gene_ids` 数组是在预处理（包括 HVG 选择，将基因从 2000 减少到 1200 个高变基因）*之前* 计算的。因此，`gene_ids` 的长度为 2000，而数据只有 1200 个特征。

**修复**：将 `gene_ids` 的计算移到 HVG 选择*之后*，确保 ids 与剩余基因匹配。

**文件**：`scripts/train_pipeline.py`（第 705-712 行）

---

### Bug 3：`AttributeError: module 'triton' has no attribute 'language'` ✅

**根因**：PyTorch 2.12.0 导入 `torch._dynamo.utils`，该模块访问 `triton.language.dtype`，但已安装的 `triton` 包是一个不完整的命名空间包，缺少 `language` 子模块。此导入发生在 `torch.optim.Adam` 初始化期间，因为 PyTorch 的 `_compile.py` 延迟导入 dynamo。

**修复**：在 `$CONDA_PREFIX/lib/python3.14/site-packages/triton/` 创建了全面的 triton 存根（`__init__.py`、`language/__init__.py`、`compiler/compiler.py`、`runtime/autotuner.py` 等），以满足 PyTorch 的导入要求。将命名空间包转换为带有 `triton/__init__.py` 的常规包。

**文件**：`$CONDA_PREFIX/lib/python3.14/site-packages/triton/__init__.py`（新建），`$CONDA_PREFIX/lib/python3.14/site-packages/triton/language/__init__.py`（新建），以及其他存根。

---

### Bug 4：`run.sh` 参数顺序问题 ✅

**根因**：`run.sh` 将用户参数（`"$@"）放在*默认参数之前*，意味着默认值会覆盖用户的覆盖值（例如，`--epochs 30` 即使传递了 `--epochs 5` 也会生效）。

**修复**：交换了参数顺序，使得 `"$@"` 出现在*所有默认参数之后*，以使用户覆盖值优先。

**文件**：`run_log/run.sh`（第 86、123 行）
