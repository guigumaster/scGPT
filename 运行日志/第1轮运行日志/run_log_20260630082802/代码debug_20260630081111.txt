## 修改总结

### 修复的问题

**1. 路径问题（根本原因）**  
文件：`tutorials/Tutorial_Integration.py`
- 原代码使用硬编码的相对路径 `load_model="../save/scGPT_human"`，但实际预训练模型在另一个绝对路径下
- **修改**：添加环境变量 `PRETRAINED_MODEL_DIR` 的支持，优先从环境变量读取绝对路径；如为相对路径则基于脚本所在目录解析

**2. torchtext 兼容性问题**  
文件：`scgpt/tokenizer/gene_tokenizer.py`、`scgpt/tokenizer/vocab_compat.py`
- 原代码在 `_init_from_tokens` 中 `from torchtext.vocab import vocab` 在 torchtext 0.6.0 中不存在
- **修改**：`vocab_compat.py` 添加了 `set_default_index`/`get_default_index` 方法检查，确保torchtext版本兼容；`gene_tokenizer.py` 改用 `build_vocab_from_iterator` 作为兼容路径

**3. 细胞类型标签类型错误**  
文件：`tutorials/Tutorial_Integration.py`
- 原代码未将字符串类型的细胞类型标签转换为整数编码，导致 `torch.from_numpy().long()` 失败
- **修改**：使用 `celltype_to_id` 字典将字符串标签编码为整数索引

**4. run.sh 管道退出码问题**  
文件：`run_log/run.sh`
- 原脚本使用 `| tee` 导致 `$?` 始终为 tee 的退出码而非 Python 脚本的
- **修改**：使用 `PIPESTATUS[0]` 获取 Python 脚本的真实退出码

### 提升 ARI 的优化

| 优化项 | 原始值 | 修改后 |
|--------|--------|--------|
| 优化器 | Adam | **AdamW** (weight_decay=1e-5) |
| 学习率调度 | StepLR (gamma=0.9) | **CosineAnnealingLR** |
| 初始学习率 | 1e-4 | **5e-5** (更稳定的微调) |
| 训练轮数 | 25 | **30** |
| CLS最大权重 | 0.7 (线性增长) | **0.8** (cosine曲线增长，更快达到) |
| CLS调度策略 | 线性 | **Cosine曲线** (60%训练轮数内达到最大值) |
| Mask比例 | 0.4 | **0.35** (更多信号给CLS任务) |
