## Summary of Changes

### Root Cause Analysis
The original pipeline failed with **OOM (exit code 137)** at epoch 10 of the perturbation task due to:
1. **`num_workers=2` with `fork()` start method** - caused gradual memory accumulation and deadlocks (visible in the `DeprecationWarning` log messages)
2. **Missing `gc.collect()` between epochs** - tensor references accumulated across epochs
3. **Heavy evaluation during training** (scIB metrics + UMAP) at every 5 epochs added memory pressure
4. **args.json architecture mismatch** - saved model architecture didn't match actual model weights

### Files Modified

#### 1. `data/finetune_perturbation_pctaim.py`
- Added `torch.multiprocessing.set_start_method('spawn')` to avoid fork deadlocks
- Changed `num_workers=0` in all DataLoaders
- Reduced `batch_size=16→8`, increased `gradient_accumulation_steps=2→4`
- Increased `save_eval_interval=5→10` (only evaluate at end)
- Set `use_grad_ckpt=True` (always enable gradient checkpointing)
- Added `gc.collect()` between epochs
- Fixed architecture detection: save actual model dims to `args.json`, detect from checkpoint weights

#### 2. `data/finetune_integration_pctaim.py`
- Same multiprocessing, num_workers, batch_size, grad_accum, save_eval_interval fixes
- Same gradient checkpointing, gc.collect, architecture detection fixes
- Fixed model architecture detection to read actual checkpoint weight dimensions

#### 3. `data/finetune_replogle_pctaim.py`
- Same multiprocessing, num_workers, grad_accum, save_eval_interval fixes
- Same gradient checkpointing, gc.collect, architecture detection fixes

#### 4. `run_log/run.sh`
- Added `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1` to prevent thread contention
- Changed `num_workers=0` in all task commands
- Reduced `batch_size=16→8` for perturbation
- Increased `warmup_epochs=2→3` for all tasks
- Added GPU memory monitoring before each run
- Added `gc.collect()` to cleanup function
